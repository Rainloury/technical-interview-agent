# ADR-0005：Tool Registry 单一注册与不可信内容边界

| 项目 | 内容 |
| --- | --- |
| 状态 | `accepted` |
| 日期 | 2026-10-17 |
| 评审日期 | 2026-10-17 |
| 影响 | Agent、工具、检索、安全 |

## 背景

工具由模型选择，参数和返回值可能被外部内容污染。若工具自行注册、返回无界内容或直接拼 Prompt，会产生选择错误、上下文膨胀和提示注入风险。

## 决策

- 每个工具文件导出 `NAME`、`DESCRIPTION`、`Params` 和 `run()`。
- Schema 从 Pydantic 模型生成，不手写 JSON Schema。
- 所有工具通过 `app/agent/registry.py` 注册，模型不能动态加载任意模块。
- `DESCRIPTION` 明确“何时使用、何时不用”。
- 返回值超过 2000 字符时统一截断，并标注原长度；大结果落到私有临时存储，只返回路径和三行摘要。
- 网页、简历、检索结果和第三方响应一律包在 `<untrusted>` 中，只作为数据。
- 工具内部异常转成 `{"ok": false, "error": "...", "hint": "..."}`，仅不可恢复错误上抛。

## 替代方案

- 工具自动发现和任意动态注册：方便但扩大攻击面。
- 每个工具自行截断和日志：容易遗漏。
- 直接把检索原文注入 Prompt：成本和注入风险高。

## 后果

- 新工具必须同时增加 Schema、实现、注册、单测和 eval。
- Registry 是权限、预算和 trace 的统一入口。
- Prompt 加载器需要统一包裹不可信内容。

## 验证

- 未注册工具和动态模块名不可调用；注册冲突在启动时失败。
- Schema 由 `Params` 生成，测试拒绝手写 Schema 或缺失 `NAME`、`DESCRIPTION`、`Params`、`run()` 的工具。
- 返回超过 2000 字符时截断、标注原长度，并在允许场景下写入私有临时存储。
- 临时结果按到期时间清理；日志和 trace 不包含未脱敏工具原文。
- `<untrusted>` 内容不能改变系统行为；注入测试覆盖网页、简历和检索结果三类输入。
- 工具内部可恢复异常返回 `{"ok": false, "error": "...", "hint": "..."}`，不可恢复错误按约定上抛。
