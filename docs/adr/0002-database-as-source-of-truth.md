# ADR-0002：PostgreSQL 作为业务事实与幂等来源

| 项目 | 内容 |
| --- | --- |
| 状态 | `accepted` |
| 日期 | 2026-10-17 |
| 评审日期 | 2026-10-17 |
| 影响 | 数据、异步任务、面试恢复、错题 |

## 背景

系统需要跨设备恢复面试、保证单轮只评分一次、错题只写一次，并支持异步任务重放。Redis 可以加速短期限流和缓存，但不能承担唯一业务事实。

## 决策

- PostgreSQL 保存用户、简历任务、问答、面试、轮次、追问链、评分、报告、错题和审计。
- Redis 仅用于短期锁、限流、SSE 游标缓存和可重建状态。
- 幂等以数据库唯一约束为准：轮次回答、错题、异步任务和评分尝试均有唯一键。
- 关键状态迁移在事务内使用行锁或条件更新。
- 对象存储只保存原始文件和大型临时结果，数据库保存对象键、哈希、状态和到期时间。

## 替代方案

- Redis 作为状态主存储：快，但恢复、审计和跨设备一致性难。
- 事件溯源为主：可追溯，但首版复杂度和迁移成本过高。
- 直接文件系统保存业务状态：部署和多实例不可靠。

## 后果

- 数据库承担队列和并发压力，需要通过索引、租约和分页控制。
- 恢复、评审计费和错题幂等更容易验证。
- 数据库成为主要容量和备份目标。

## 验证

- 并发提交、重复键、网络重试和 Worker 崩溃测试。
- 恢复后预算和状态不重置。
- 数据库备份恢复演练。
- 清空 Redis 后，已提交回答、面试状态、任务租约和报告可用性仍可从 PostgreSQL 恢复。
- 所有 Redis 键必须能标注为锁、限流或可重建缓存；无法重建的键不得进入 Redis 单独作为事实来源。
