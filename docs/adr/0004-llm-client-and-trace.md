# ADR-0004：统一 LLM Client 与调用 Trace

| 项目 | 内容 |
| --- | --- |
| 状态 | `accepted` |
| 日期 | 2026-10-17 |
| 评审日期 | 2026-10-17 |
| 影响 | LLM、Agent、成本、日志、测试 |

## 背景

项目需要精调 Prompt、重试、token 计数和成本。如果每个业务模块直接调用厂商 SDK，trace、超时、费率和日志脱敏会分散，无法定位模型回归。

## 决策

- 所有模型调用只经过 `app/llm/client.py`。
- 模型名只从 `app/llm/models.py` 的 `FAST`、`DEFAULT`、`REASONING` 读取。
- Client 统一设置超时、重试、结构化输出校验、费率、token 预算和 trace。
- 每次调用记录模型档位、Prompt 名称和版本、输入输出 token、延迟、重试、工具调用和请求 ID。
- 业务模块只接受已验证的结构化结果，不接触厂商原始响应对象。
- 日志不记录完整 Prompt、简历、回答或未脱敏内容。

## 替代方案

- 每个业务模块直接调用 SDK：灵活但不可追踪。
- 引入智能体框架统一调用：隐藏关键控制点，不符合约束。
- 只记录最终业务结果：无法定位成本和失败阶段。

## 后果

- Client 是关键路径，需要独立单测和故障注入。
- 新模型或档位只需改配置和模型映射。
- 评测和成本分析依赖统一 trace 字段。

## 验证

- 超时、限流、Schema 失败、重试和取消。
- 每个调用产生完整 trace，字段与[技术设计追踪清单](../technical-design.md#83-追踪)一致。
- trace 记录业务关联 ID，但不包含完整 Prompt、简历、回答、参考答案或未脱敏内容。
- 日志脱敏和敏感字段白名单对成功、失败和重试路径均生效。
- Prompt 或模型档位变化触发 eval。
- 通过依赖检查或测试确认业务模块不能绕过 Client 直接调用厂商 SDK。
