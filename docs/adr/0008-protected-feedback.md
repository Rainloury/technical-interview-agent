# ADR-0008：受保护反馈按整场终态解锁

| 项目 | 内容 |
| --- | --- |
| 状态 | `accepted` |
| 日期 | 2026-10-17 |
| 决策者 | 项目负责人 |
| 评审日期 | 2026-10-17 |
| 影响 | 面试提交、报告、错题、薄弱点 |

## 背景

需求要求面试结束前不展示详细评分、参考答案、错题和薄弱点，同时评分又需要保存并在结束后生成报告。若提交接口直接返回分数，会绕开受保护反馈规则，并可能让用户通过分数探测后续问题。

## 决策

- 内部评分和用户可见反馈在数据模型和 DTO 上分离。
- 回答提交只返回 `202 Accepted`、接收状态和中性进度；`DR-02` 已批准该公开边界。
- 只有面试进入终态，且所有已接收轮次都已离开 `scoring` 后，才设置 `feedback_unlocked_at` 并返回受保护反馈。
- 已接收轮次永久评分失败时必须转为明确、可解释的 `scoring_failed` 终态条件，不能无限停留在 `scoring`，也不能伪造分数或写入错题。
- 报告可返回已成功评分轮次，同时带 `incomplete_scoring` 或稳定状态说明；不得为了凑完整报告暴露未完成轮次的中间分数、参考答案、失分原因或追问依据。
- 报告、错题详情和薄弱点接口在未解锁时返回统一的受保护状态；同一场终态面试后续恢复评分时，可在原终态内重新生成或更新报告，不通过新面试或新会话绕过解锁。
- SSE、错误响应、导出和调试端点使用同一权限裁剪。
- 未作答、跳过和评分失败轮次不进入错题。

## 替代方案

- 提交后立即返回分数：反馈强但违反当前受保护内容规则。
- 面试结束立即生成报告且不等待评分：响应快但可能把中间状态当作最终反馈。
- 只在前端隐藏：无法防止接口泄露。

## 后果

- 面试提交响应信息较少，需要中性流程反馈。
- 需要终态聚合、永久评分失败状态、报告完整性标记和解锁时间字段。
- 评分恢复与报告重生成必须保持同一面试终态和同一 `feedback_unlocked_at` 语义，不能重新开放提交。
- 测试必须覆盖接口、SSE、报告、错题和导出。

## 验证

- 面试进行中无法获得分数、答案、错题详情或追问依据。
- 终态但仍有已接收轮次处于 `scoring` 时不设置 `feedback_unlocked_at`，报告返回 `409 report_not_ready`。
- 永久评分失败转为说明明确的 `scoring_failed` 后允许解锁；报告可返回已成功轮次并标记 `incomplete_scoring`，且不泄露失败轮次的中间评分或参考答案。
- 评分失败轮次不写错题；后续评分恢复仍保持同一终态，并只通过报告更新展示结果。
- 越权、已删除资源和不存在的资源不泄露存在性。
