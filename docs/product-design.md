## 1. 方案摘要

产品定位为面向技术求职者的个人面试训练工作台，不是通用聊天工具。P0 将三条用户任务闭环放在同一登录账号下：

1. `简历 -> 结构化分析 -> 针对性面试题`
2. `技术问题 -> 检索增强回答 -> 证据与延伸问题`
3. `模拟面试 -> 逐轮回答与评分 -> 按分数有界追问 -> 完整报告`

模拟面试结束后，失败轮次自动进入错题集，并聚合为薄弱知识点。用户可在历史记录中按账号跨设备继续查看任务、问答、面试、错题和薄弱点。

核心产品原则：

- **结果可信**：关键事实优先关联证据；无证据时明确标注模型知识或拒答。
- **规则透明**：评分权重、通过阈值和追问预算由确定性规则执行。
- **反馈延后**：面试进行中不展示分数、参考答案、评分标准或错题结论。
- **用户可控**：用户可以跳过当前追问、结束当前追问链，并随时删除个人数据。
- **有界智能**：题目数量、追问深度、回答次数、时间、token 和重试都受上限约束。

## 2. 产品定义

### 2.1 目标用户

准备后端、前端或全栈技术岗位面试的个人求职者。P0 仅服务单个个人账号，不提供企业招聘、真人面试官或多人协作能力。

### 2.2 核心问题

| 用户问题 | 产品解法 | 用户获得的价值 |
| --- | --- | --- |
| 不知道简历会被如何追问 | 从简历证据生成技能、项目和缺口，再出题 | 练习更贴近真实经历 |
| 单题答案零散，容易遇到错误信息 | 限定知识源检索、证据引用和不确定性表达 | 更快形成可信的技术理解 |
| 缺少连续回答、追问和评分的压力 | 有界追问式模拟面试 | 检验知识深度和临场表达 |
| 答错后没有沉淀 | 错题、参考答案、失分原因和薄弱点聚合 | 形成可重复的复习闭环 |

### 2.3 核心价值闭环

```text
识别经历与目标方向
  -> 练习针对性问题
  -> 完成有界模拟面试
  -> 获得评分与追问树
  -> 收集错题和薄弱点
  -> 安排后续复习
```

### 2.4 产品不做什么

- 不做通用闲聊或生活助手。
- 不做模型训练、微调或长期能力画像。
- 不自动联系招聘方、投递简历或执行外部写操作。
- 不提供真人面试、音视频面试或语音识别。
- 不让用户上传任意 URL 或文件作为 P0 检索源。
- 不把单次评分解释为对用户能力、人格或职业前景的定论。

## 4. 关键用户旅程

### 4.1 首次使用

```text
注册或登录
  -> 进入工作台
  -> 选择“上传简历”“技术问答”或“开始模拟面试”
  -> 完成首次任务
  -> 在工作台看到历史结果和下一步建议
```

首次使用不安排长篇产品介绍。工作台直接展示可执行入口、输入限制和最近进度；未登录用户只能看到登录、注册和找回密码入口。

### 4.2 简历到面试题

```text
上传简历
  -> 本地预校验
  -> 服务端校验并创建任务
  -> 展示解析和分析进度
  -> 查看技能、项目和缺口
  -> 查看 10 道针对性面试题
```

成功标准：

- 用户可在失败后创建新任务，原任务保留审计记录。
- 每道题关联至少一个技能或项目证据。
- 信息不足时显示“未验证”，不补写工作经历、公司或业绩数字。
- 题目难度分布为简单 30%、中等 50%、困难 20%。

### 4.3 技术问答

```text
输入技术问题
  -> 展示正在检索
  -> 首段内容流式显示
  -> 流结束后补齐证据、限制条件和延伸问题
  -> 用户选择继续提问或保存记录
```

成功标准：

- 有充分证据时，关键事实关联可查看的来源标题、章节位置和短片段。
- 证据不足时标注“基于模型知识”；模型不确定时明确拒答。
- 延伸问题必须与当前主题相关，并标记为建议问题。
- 用户输入不能扩大知识源范围或改变系统规则。

### 4.4 模拟面试与复盘

```text
选择方向、难度和主题
  -> 生成 5 个主问题蓝图
  -> 逐题回答并独立评分
  -> 通过且达到 85 分时生成下一层追问
  -> 未通过、跳过、达到上限或主题饱和时结束当前链
  -> 完成全部主问题
  -> 展示完整追问树、逐轮结果、错题和薄弱点
```

成功标准：

- 面试进行中只展示当前题，不提前显示答案、分数或评分标准。
- 每轮只接受一次回答，网络重试不产生重复评分。
- 父问题通过不替代子追问评分；子追问失败仍写入错题。
- 每条追问链最多 2 层追问、3 次回答。
- 整场默认 5 个主问题，服务端在 40 分钟到达时硬截止。
- 已提交轮次、当前题目和剩余预算跨设备恢复；未提交草稿仅保存在原设备。
- 整场结束后才统一解锁错题、参考答案、详细评分和薄弱点。

## 5. 页面方案

### 5.1 登录页

目标：完成身份认证并将用户带入个人工作区。

页面内容：

- 产品名称与一句功能说明。
- 邮箱、密码输入和登录按钮。
- “创建账号”和“忘记密码”入口。
- 隐私与数据保留说明入口。
- 加载、失败、账号不可用和网络异常状态。

交互规则：

- 未登录时不允许访问业务页面或通过 API 获取业务数据。
- 登录失败不泄露账号是否存在；邮箱不存在和密码错误使用同一文案。
- 登录成功后优先回到用户原本访问的页面；无目标页面时进入工作台。
- 会话 Cookie 仅由服务端设置，页面脚本不读取或持久化会话令牌。

### 5.1.1 注册页

页面内容：

- 邮箱、密码和确认密码。
- 密码规则说明和提交按钮。
- 返回登录入口。

交互规则：

- 注册成功后不建立会话，统一进入登录页并给出中性提示；用户随后通过登录进入工作台。
- 已注册邮箱和未注册邮箱的公开响应不可区分，避免账号枚举。
- 注册提交按账号和来源维度限流；达到限制时显示可重试时间。
- 创建账号不得绕过邮箱格式校验、密码强度校验或隐私说明。

### 5.1.2 找回密码页

页面内容：

- 邮箱输入和提交按钮。
- 返回登录入口。

交互规则：

- 无论邮箱是否存在或邮件是否实际发送，都显示同一中性提示。
- 邮件发送失败时允许稍后重试，但不提示具体账号状态。
- 重置链接短时有效且只能使用一次；令牌不得出现在页面文案、埋点或日志中。

### 5.1.3 重置密码页

页面内容：

- 新密码和确认密码。
- 提交按钮及链接无效、过期或已使用状态。
- 返回登录入口。

交互规则：

- 重置成功后撤销该账号全部旧会话，并要求用户重新登录。
- 链接无效、过期或已使用统一提示，不提供账号存在性信息。
- 页面不在 URL 之外持久化重置令牌，不把令牌写入客服文案或错误上报。

### 5.2 工作台

目标：让用户在 10 秒内知道“从哪里继续”和“下一步练什么”。

首屏结构：

1. 页面标题与“新建”入口。
2. 继续当前面试或未完成任务的显著提示。
3. 最近简历任务、最近问答、最近面试三个摘要区域。
4. 高频薄弱点和最近错题摘要。
5. 隐私与数据保留提示。

空状态：

- 无任务：提供上传简历、提问和开始模拟面试三个明确动作。
- 无错题：说明完成模拟面试后会在此形成复习记录。
- 无薄弱点：说明需要至少一次失败轮次才会聚合。

### 5.3 简历上传与任务页

上传区：

- 主按钮为“上传简历”。
- 明确展示支持 PDF、DOCX，最大 10 MB、最多 10 页。
- 明确展示不支持扫描件、图片或 OCR。
- 上传前进行类型和大小预校验，服务端再次校验。

任务状态：

| 状态 | 用户可见文案 | 可用动作 |
| --- | --- | --- |
| 已上传 | 简历已保存，等待解析 | 查看进度 |
| 解析中 | 正在提取简历文本 | 查看进度 |
| 分析中 | 正在识别技能和项目 | 查看进度 |
| 出题中 | 正在生成针对性题目 | 查看进度 |
| 已完成 | 简历分析和题目已生成 | 查看结果、重新上传 |
| 失败 | 显示可理解失败原因 | 重新提交任务 |
| 原始文件已删除 | 原始简历已删除，仅保留不可恢复正文的脱敏摘要 | 查看脱敏结果 |

任务详情：

- 简历摘要：技能、项目、职责、成果、证据和未验证项。
- 题目列表：题干、类别、难度和考察方向；参考答案与评分标准不在回答前展示。
- 出题理由：P1 展示更完整的简历证据关联。
- 重新生成或筛选：仅在对应 P1 能力启用后出现。

关键交互：

- 上传成功后立即返回任务 ID 和状态，不等模型完成。
- 页面刷新或更换设备后可继续查看任务状态。
- 失败任务不能原地覆盖；重新提交时创建独立任务。
- 删除原始文件后，界面明确标记残留内容为脱敏衍生数据。
- 每条证据摘要最多 200 个字符；删除后不展示原文引用、页码定位、文件名或可拼接恢复正文的上下文。

### 5.4 技术问答页

页面采用单列主问答区，证据与延伸问题跟随当前回答展示。

输入区：

- 支持多行问题输入和提交。
- 空输入、超长输入和非技术输入分别给出明确提示。
- 知识源说明固定展示为“官方技术文档精选与自建题库”，不接受用户指定外部 URL。

回答区：

1. 状态提示：检索中、生成中、已完成或失败。
2. 直接结论。
3. 原理与解释。
4. 示例、工程取舍和常见误区，按问题需要显示。
5. 证据来源列表。
6. 延伸问题。

证据卡：

- 展示来源标题、章节位置和短证据片段。
- 可展开查看允许展示的摘要，不展示完整原文或内部检索配置。
- 用户可点击查看证据与结论的对应关系。

证据不足：

- 使用明显但不过度醒目的提示：“未检索到充分资料，以下内容基于模型知识。”
- 对不确定事实直接说明无法确认，不生成伪造引用。
- 不把“基于模型知识”做成免责声明式的统一尾注；必须放在对应内容附近。

流式交互：

- 首段内容到达前显示检索或生成状态。
- 流式期间允许停止生成；停止后保留已生成内容并标记未完成。
- 流结束后一次性补齐结构、证据和延伸问题。
- 网络中断后不自动重复扣费生成；提供重新生成或查看已保存结果。

延伸问题：

- 仅作为可点击建议，不自动加入错题集或题库。
- 点击后带入输入框，由用户确认后重新提问。

### 5.5 创建模拟面试

配置项：

| 字段 | P0 | 默认值 | 规则 |
| --- | --- | --- | --- |
| 面试方向 | 是 | 无，必须选择 | 后端、前端、全栈 |
| 难度 | 是 | 中等 | 影响题目难度分布 |
| 主题 | 是 | 自动覆盖 | 可限定重点技术主题 |
| 可选 JD | 否，P1 | 空 | 仅在 P1 启用后展示 |

确认区：

- 固定展示“5 个主问题、40 分钟硬截止、每条追问链最多 2 层追问”。
- 明确说明倒计时在开始后持续运行，离线或关闭页面期间不暂停。
- 明确提示“面试结束前不展示分数、参考答案和详细反馈”。
- 主按钮为“开始模拟面试”。

创建规则：

- 创建成功后返回面试 ID、5 题蓝图摘要、服务端截止时间和当前题目。
- 不放宽主问题数量、追问深度或回答次数。
- 面试方向写入面试记录，并在报告和错题中保持一致。
- 每个方向使用独立的核心主题、允许知识源和评分锚点；三个方向共享通用检索、出题和评分框架。

### 5.6 模拟面试进行页

页面目标：让用户专注于当前问题，不因评分信息或历史题干扰作答。

固定区域：

- 面试方向与当前进度，例如“第 2 个主问题 / 共 5 个”。
- 当前追问层级，例如“主问题”或“追问 1/2”。
- 基于服务端截止时间展示的剩余时间，客户端时钟不参与判定。
- 当前追问链的预算状态。
- 中断恢复入口或退出说明。

题目区：

- 只展示当前主问题或当前追问。
- 主问题可展示关联技能或项目类型，不展示隐藏评分标准。
- 追问必须体现与父回答的关联，不重复父题。

回答区：

- 多行文本输入，显示字数或长度上限。
- 提交前提示“每题只能提交一次”。
- 提交后立即锁定当前轮次，显示“回答已记录”。
- 提交失败或评分失败时保留回答内容，提供有限重试或恢复路径。

面试进行中的反馈边界：

- 不显示分项分数、加权总分、通过/不通过、错题通知或参考答案。
- 不因分数低而展示“你不合格”等能力评价。
- 只展示中性流程状态，例如“回答已保存”“正在准备下一题”“评分暂时不可用”“当前追问链已结束”。
- 可以展示已提交轮次、主问题完成数、剩余题数和剩余时间。
- 不展示通过趋势、预测分数、关键错误提示、下一步是否会生成追问或任何追问依据。
- 是否通过只用于驱动下一题分支，结果在整场结束后统一展示。

高分追问：

```text
提交回答
  -> 独立评分
  -> 总分 >= 85 且无关键错误
  -> 生成下一层相关追问
  -> 用户继续回答
```

结束当前追问链：

- 用户可点击“跳过此题”或“结束当前追问”。
- 二次确认需说明：已提交结果会保留，但不能修改。
- 当前链结束后进入下一主问题。
- 跳过未回答的追问不计入错题；已评分失败的轮次才计入错题。
- P0 不提供“提前结束整场”；该能力推迟到 P1，使用独立操作和二次确认。
- 跳过、结束当前追问链和结束整场分别记录不同原因，不互相复用状态。

恢复：

- 页面刷新、网络中断或重新登录后，从最后持久化的精确轮次继续。
- 恢复后不重复评分，不重新获得完整追问预算。
- 已提交轮次、当前题目和剩余时间随登录账号跨设备恢复；离线期间继续计时。
- 当前输入未提交时，可在原设备的同一浏览器中恢复本机草稿；草稿不写入服务端、不跨设备同步，提交成功或退出登录后清除。

时间截止：

- 服务端保存整场截止时间，进入 40 分钟截止时立即锁定新回答和追问提交。
- 截止前已接收的回答继续完成评分；截止后完成的结果仍进入同一场报告。
- 未作答或未提交的题目标记为“未作答”，不写入错题和薄弱点。
- 页面展示“本场面试已结束”，提供查看已解锁报告的入口，不提供延长时间的操作。

### 5.7 面试报告页

报告仅在整场面试结束后可访问完整内容。

摘要区：

- 面试方向、开始与结束时间、实际用时。
- 主问题数、追问数、通过数、未通过数和未作答数。
- 主题表现摘要。
- “查看错题”“查看薄弱点”“导出 PDF（P1）”操作。

完整追问树：

```text
Q1 主问题（通过）
  ├─ Q1.1 追问 1（通过）
  │   └─ Q1.1.1 追问 2（未通过）
  └─ Q1.2 跳过
Q2 主问题（未通过）
```

每轮卡片至少包含：

- 题目原文。
- 轮次类型和层级。
- 用户回答。
- 分项分数和加权总分。
- 通过、未通过、跳过或未作答状态。
- 失分原因和简短反馈。
- 参考答案。
- 与薄弱知识点的关联。

展示规则：

- 主问题和子追问按父子关系展示，不能只按时间平铺。
- 失败子轮次既出现在追问树中，也汇总到错题摘要和薄弱点。
- 未作答和跳过不自动记为错题。
- 关键事实错误或严重安全错误明确标记为一票否决，并展示触发原因。
- 反馈描述具体知识缺口，不使用人格、智力或胜任力断言。

### 5.8 错题列表与详情

列表默认按最近发生时间倒序，支持日期、主题、难度和掌握状态筛选；P0 至少提供主题与时间筛选。

错题卡摘要：

- 题目原文。
- 主题、难度和来源面试。
- 失败时间与分项得分。
- 一句话失分原因。

详情内容：

- 题目及父子关系。
- 用户原回答。
- 参考答案。
- 分项得分、加权总分和关键错误。
- 失分原因与正确思路。
- 关键知识点和可执行复习建议。
- 来源面试和轮次链接。

权限规则：

- 面试未结束时，列表和详情均不得返回答案或详细评分。
- 跨设备查看仍需通过所有者鉴权。
- P1 重练结果独立保存，不覆盖原错题和原评分。

### 5.9 薄弱知识点页

页面先展示聚合薄弱点，再下钻到来源错题。

每个薄弱点包含：

- 主题名称和简短解释。
- 严重程度、失败次数和最近发生时间。
- 关联考察点与失败轮次。
- 应复习的概念。
- 改进方向和可执行的练习目标。
- 来源错题入口。

默认排序：

1. 严重程度。
2. 失败次数。
3. 最近发生时间。

交互规则：

- 不展示脱离失败证据的薄弱点。
- 同一主题多次失败合并展示，但保留全部来源轮次。
- P1 支持按薄弱点筛选错题和人工修正分类；P0 不提供分类修改。

### 5.10 历史与隐私设置

历史页按更新时间倒序分页展示简历任务、问答和面试报告。

隐私设置至少提供：

- 删除原始简历：立即取消原始文件访问，保留脱敏分析、错题和薄弱点。
- 删除全部业务数据：删除账号下原始文件、分析、问答、面试、错题和薄弱点，并生成审计摘要。
- 查看保留期限：原始简历 30 天，分析及面试相关数据 90 天。

删除操作必须有明确影响范围和二次确认。删除完成页面不得继续展示敏感内容。

审计摘要只展示操作类型、资源类型、结果、时间和请求标识，保留 365 天；不得包含简历正文、完整回答、参考答案、证据原文或可逆个人标识。

## 6. 核心业务规则

### 6.1 简历任务

| 事项 | 规则 |
| --- | --- |
| 文件类型 | PDF、DOCX |
| 文件大小 | 不超过 10 MB |
| 页数 | 不超过 10 页 |
| 不支持 | 扫描件、图片简历、OCR 文本 |
| 默认题量 | 10 道 |
| 难度分布 | 简单 30%、中等 50%、困难 20% |
| 失败恢复 | 原任务保留，新任务使用新 ID |
| 原始文件保留 | 30 天 |
| 衍生数据保留 | 90 天 |

### 6.2 技术问答

| 事项 | 规则 |
| --- | --- |
| 知识源 | 官方技术文档精选、项目自建题库 |
| 外部 URL | P0 不接受 |
| 证据展示 | 标题、章节位置、短片段 |
| 证据不足 | 标注模型知识；不确定时拒答 |
| 输出 | 流式回答，结束后补齐证据和延伸问题 |
| 延伸问题 | 只作为建议，不自动写入其他业务数据 |

### 6.3 模拟面试配置与预算

| 事项 | 默认值 | 上限或规则 |
| --- | --- | --- |
| 面试方向 | 必须选择 | 后端、前端、全栈 |
| 主问题 | 5 | 固定为 5 |
| 整场截止 | 40 分钟 | 服务端硬截止；中断和离线期间持续计时 |
| 未提交草稿 | 本机保存 | 不写入服务端，不跨设备同步 |
| 每个主问题追问层数 | 最多 2 层 | 达到后结束当前链 |
| 每条追问链回答次数 | 最多 3 次 | 包含主问题回答 |
| 答案提交次数 | 每轮 1 次 | 重复提交不重复评分 |
| 总分计算 | 确定性代码 | 不由模型直接决定 |
| 反馈解锁 | 整场结束后 | 之前不返回分数、答案和薄弱点 |

方向配置规则：

- 后端、前端、全栈共享题目 Schema、检索流程、评分权重和 eval 框架。
- 每个方向独立维护核心主题清单、知识源白名单、题型模板和评分锚点。
- 三个方向可以使用同一套物理知识库，但检索必须按方向的来源白名单和主题范围过滤。
- 全栈不是前后端题目简单拼接，必须覆盖接口契约、认证链路、状态同步和端到端故障处理。

### 6.4 方向覆盖深度

每个方向定义 8 个 P0 核心主题，并选择 3 个主题达到 L3 设计取舍深度。

| 方向 | P0 核心主题 | L3 重点主题 |
| --- | --- | --- |
| 后端 | HTTP/API 与幂等；运行时与并发；数据库、事务与索引；缓存与一致性；消息与异步重试；认证与安全；可观测性与排障；服务设计与可用性 | API 幂等；数据库事务；缓存一致性 |
| 前端 | HTML/CSS、响应式与无障碍；JS/TS 与事件循环；组件状态与数据流；浏览器网络与安全；渲染性能；表单与错误状态；测试与调试；构建与缓存 | 事件循环；渲染性能；浏览器安全 |
| 全栈 | API 契约与校验；认证与会话；数据建模与事务；前后端状态同步；异步任务与最终一致性；端到端错误与重试；端到端性能与缓存；部署、安全与可观测性 | 认证链路；状态同步；端到端幂等 |

覆盖规则：

- 每个核心主题至少达到 L1 概念理解和 L2 场景应用。
- 每个方向至少 3 个主题达到 L3 设计取舍和工程判断。
- 每场 5 个主问题至少覆盖 4 个不同主题，同一主题最多出现 2 次，并至少覆盖 1 个 L3 重点主题。
- P0 使用通用原理题，参考技术栈为 Python/FastAPI、PostgreSQL/Redis 和 TypeScript/React，不承诺框架专深题。
- 分布式共识、编译器或内核、移动原生、机器学习和深度 SRE 不纳入 P0。

### 6.5 评分与分支

评分维度：

| 维度 | 权重 | 主要观察点 |
| --- | ---: | --- |
| 正确性 | 35 | 关键事实、概念和结论是否正确 |
| 技术深度 | 25 | 原理、边界、取舍和迁移能力 |
| 工程判断 | 20 | 实际场景中的方案选择、风险和可维护性 |
| 完整性 | 10 | 是否覆盖问题的主要部分 |
| 表达清晰度 | 10 | 结构、逻辑和可理解程度 |

确定性规则：

- 分项分数和权重之和必须可校验。
- 加权总分由固定公式计算。
- `<70`：不通过。
- `70–84`：通过，但不生成追问。
- `>=85`：通过，且无关键错误时生成下一追问。
- 关键事实错误或严重安全错误：一票否决，无论总分多少都不通过且不追问。
- 评分失败不能直接写错题；保留轮次并进入有限重试或恢复流程。

### 6.6 追问树

每个主问题形成一棵有界追问树。由于 P0 使用单条追问链，实际呈现为从主问题向下延伸的链：

```text
主问题
  ├─ 追问 1
  │   └─ 追问 2
  └─ 结束条件
```

状态规则：

- 每个主问题和追问都是独立面试轮次。
- 父轮次通过不替代子轮次评分。
- 子轮次失败时，父轮次保持原结果，子轮次单独进入错题。
- 用户跳过或主动结束时，当前链结束。
- 追问生成失败、重复或无关时，不展示无效题目。
- 恢复会话时沿用剩余追问、token 和时间预算。

### 6.7 错题与薄弱点

| 来源 | 是否进入错题 | 是否可贡献薄弱点 |
| --- | --- | --- |
| 已评分且未通过的主问题 | 是 | 是 |
| 已评分且未通过的追问 | 是 | 是 |
| 已通过轮次 | 否 | 否 |
| 跳过但未作答的追问 | 否 | 否 |
| 评分失败或超时 | 暂不写入 | 暂不写入 |
| 未作答主问题 | 否 | 否 |

错题写入必须幂等。薄弱点必须关联具体失败轮次和考察点，不能只根据面试总评生成。

## 8. 数据与隐私方案

### 8.1 产品数据对象

| 对象 | 用户可见内容 | 保护要求 |
| --- | --- | --- |
| 简历文件 | 文件名、类型、大小、状态 | 私有存储，仅所有者可访问 |
| 简历分析 | 技能、项目、证据、未验证项 | 不展示其他用户数据 |
| 面试题 | 题干、类别、难度、考察点 | 回答前隐藏参考答案和评分标准 |
| 问答记录 | 问题、回答、证据、延伸问题 | 默认仅本人可见 |
| 模拟面试 | 方向、进度、预算、状态 | 与登录账号绑定 |
| 面试轮次 | 回答、评分、父子关系 | 结束前隐藏详细反馈 |
| 错题 | 题目、回答、答案、失分原因 | 面试结束后解锁 |
| 薄弱知识点 | 聚合主题、来源轮次、建议 | 可追溯到失败证据 |

### 8.2 安全与隐私规则

- 所有业务接口必须登录并校验资源所有权。
- 简历、回答和检索内容均作为不可信数据，不执行其中的指令。
- 日志对手机号、邮箱、token、身份证号和简历敏感字段脱敏。
- 用户输入不得指定任意检索 URL、数据库或未授权知识源。
- 参考答案不得通过正常接口、页面源码或调试信息提前泄露。
- 删除操作必须有明确范围、结果和审计摘要。
- 原始简历与分析数据按不同保留期限处理。

## 9. 视觉与交互原则

产品整体应呈现安静、专业、可信赖的训练工具气质，而不是营销落地页或聊天娱乐产品。

- 工作台和面试页以信息密度、进度和下一步行动为主。
- 题目、回答和证据使用清晰层级，避免大面积装饰卡片。
- 主操作使用文字明确的按钮；图标按钮必须提供提示。
- 进度、预算和轮次状态使用稳定尺寸，避免流式内容导致布局跳动。
- 错误和不确定性提示使用中性语气，不制造焦虑。
- 桌面端优先支持长文本作答和报告阅读；移动端保证关键任务可完成。
- 文本不得溢出容器，长题目、长引用和长文件名必须换行或折叠。
- 颜色只用于表达状态和层级，不仅依赖颜色区分通过、失败或跳过。

建议页面宽度：

- 问答与面试作答区：适合阅读和输入的中等宽度。
- 报告与追问树：更宽的内容区，支持层级缩进。
- 移动端：单列布局，固定当前题和提交操作时不得遮挡内容。

### 10.3 建议事件

## 12. MVP 交付切片

### 12.1 切片一：账号与工作台

- 自助注册、登录、退出、会话撤销和邮件找回密码。
- 工作台空状态与最近任务摘要。
- 历史记录分页和数据保留提示。

验收门槛：未登录不可访问业务数据；注册和登录不泄露账号存在性；重置密码后旧会话全部失效；跨设备登录可看到同一账号历史。

### 12.2 切片二：简历闭环

- PDF/DOCX 上传、校验和异步任务。
- 简历分析和 10 道题生成。
- 失败重试、原始文件删除和任务详情。

验收门槛：文档格式、大小、页数、扫描件、注入内容和信息不足场景均有可验证结果。

### 12.3 切片三：检索问答

- 限定知识源检索。
- 流式结构化回答。
- 证据来源、不确定性表达和延伸问题。

验收门槛：有证据、无充分证据、检索失败和任意 URL 四类场景均符合规则。

### 12.4 切片四：模拟面试

- 后端、前端、全栈方向配置。
- 5 个主问题、服务端 40 分钟硬截止和有界追问链。
- 单轮单次提交、结构化评分、确定性阈值和一票否决。
- 中断恢复、跳过追问和结束追问链。

验收门槛：70 分以下、70–84、85 分及以上、关键错误、预算上限和恢复场景全部覆盖。

### 12.5 切片五：报告与复习

- 完整追问树和逐轮结果。
- 整场结束后统一解锁错题、参考答案和详细评分。
- 错题详情、薄弱点聚合排序和复习建议。

验收门槛：失败子轮次可追溯到错题和薄弱点，父轮次结果不被覆盖，未作答轮次不计入错题。

### 12.6 切片六：上线质量

- 用户隔离、数据删除、日志脱敏和不可信内容处理。
- 模型行为评测、单测、集成测试和性能测量。
- trace、成本、失败率和追问终止原因监控。

验收门槛：需求基线中的 P0 验收场景通过，模型行为评测无超过阈值的回归。

## 14. 验收视角

产品评审时按以下顺序检查：

1. 用户是否能在不阅读说明文档的情况下完成首次任务。
2. 每个结果是否明确展示来源、限制和下一步动作。
3. 面试进行中是否没有泄露分数、答案或评分标准。
4. 不同分数段是否产生正确的下一题分支。
5. 完整追问树是否能还原真实作答路径。
6. 错题是否只来自确定性未通过的已评分轮次。
7. 薄弱点是否能追溯到具体轮次和失分原因。
8. 跨设备、刷新、网络中断和重复提交是否不破坏状态。
9. 用户删除数据后，所有入口是否停止展示相关内容。
10. 空状态、失败状态和权限拒绝是否都有可理解出口。

## 16. 上线边界

P0 上线必须包含：

- 登录、跨设备访问和用户隔离。
- 邮箱密码自助注册、登录、退出、服务端会话撤销和邮件找回密码。
- PDF/DOCX 简历上传、分析、10 道题生成。
- 官方文档精选与自建题库的检索问答、证据和流式输出。
- 后端、前端、全栈三个方向的模拟面试。
- 5 个主问题、服务端 40 分钟硬截止、最多 2 层追问和 3 次回答。
- 每个方向 8 个核心主题，至少 3 个达到设计取舍深度。
- 结构化评分、70/85 分段、关键错误一票否决。
- 单轮单次提交、跳过/结束追问、已提交轮次跨设备恢复、本机草稿恢复和统一反馈解锁。
- 完整追问树、错题和薄弱知识点。
- 数据保留、立即删除、权限、trace、日志脱敏和达到绝对门槛的模型行为评测。

P1 能力不在 P0 上线范围内：可选 JD、受控资料上传、暂停和提前结束、PDF 报告导出、错题状态、重练和人工修正薄弱点分类。
