# 私有内部资料混合 RAG 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 为每个用户增加私有资料上传、异步索引、pgvector + BM25 混合检索和前端资料库入口，并让现有技术问答自动引用当前用户已就绪资料。

**架构：** 新增 `app/rag/` 负责文件切分、Ollama `bge-m3` embedding、pgvector 与 PostgreSQL 全文两路召回及 RRF 融合；`app/services/documents.py` 负责 owner 校验、幂等上传、状态与删除；现有 `ResumeWorker` 复用租约和 fencing 处理资料索引与清理。前端新增 `/documents` 账本页，问答继续使用现有 SSE 契约。

**技术栈：** Python 3.11、FastAPI、Pydantic v2、SQLAlchemy 2.0 async、Alembic、PostgreSQL 16 + pgvector、Ollama `bge-m3`、httpx、React 19、TypeScript、Vite、TanStack Query、Vitest、Playwright。

**规格：** `docs/superpowers/specs/2026-10-21-user-rag-design.md`

## 全局约束

- 资料严格按 `owner_user_id` 隔离；他人资源与不存在资源统一 `404 resource_not_found`。
- 第一版支持 PDF、DOCX、TXT、Markdown，单文件上限 10 MB，正文上限 200000 字符。
- embedding 使用独立 Ollama `/api/embed`、`bge-m3`、1024 维；模型不可用时问答降级为 BM25 风格词法召回。
- 向量与词法各取 Top 20，RRF `k=60` 等权，融合后 Top 5。
- `qa_evidence.snippet` 最多 200 字符；公开 DTO 不返回 owner、chunk UUID、对象键或完整正文。
- 所有工具和 Prompt 中的用户资料都视为 untrusted，不执行其中指令。
- 上传后自动参与问答，不增加资料选择器；只有 `ready` 资料可检索。
- 所有写接口必须校验 CSRF、Origin/Referer 和 `Idempotency-Key`；重复请求必须幂等。
- Worker 必须使用现有单次领取、租约、fencing、有限重试和最大运行时间；禁止新增无界循环。
- 提示词修改必须同步版本号、变更说明和 eval；生产依赖版本不得静默升级。
- 不在日志、trace 或错误详情中写入资料正文、完整对象键或 embedding 向量。
- 每个任务先写失败测试，再写生产代码，验证通过后再提交。
- PostgreSQL 扩展必须在数据库级初始化；测试 schema 通过 `search_path` 隔离业务表，不重复创建扩展。

## 审查重点（Review Focus）

- 上传同名文件但内容不同：应生成独立资料记录，不能因文件名复用或覆盖旧内容。
- 同一用户上传完全相同的字节：ready 资料应返回既有结果；failed 资料应复用同一记录重新入队；不重复写对象、不产生重复 chunks。
- 另一用户持有资料 UUID 直接查询、删除或提问：应得到统一 404，且检索不泄露任何片段。
- Ollama 超时、返回维度错误或部分批量失败：问答应降级 BM25；资料索引应重试后失败，不能写入部分向量。
- 资料被删除或账号删除时 Worker 仍在运行：迟到写入必须被 fencing 和状态条件拒绝，已删除资料不得重新进入检索。
